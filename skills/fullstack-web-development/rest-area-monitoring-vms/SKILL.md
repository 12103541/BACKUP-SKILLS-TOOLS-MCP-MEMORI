# REST AREA MONITORING SYSTEM — VMS project

FastAPI + SQLite (WAL) + YOLOv8n + WebSocket. Path: `C:\REST AREA MONITORING SYSTEM`. Login (2026-08-02): admin/password123, petugas/petugas123. Server prod port 8090; test port 9099 via `PORT=9099 python run.py`.

## Architecture map

- `app/main.py` — FastAPI app, all REST endpoints, auth helpers: `_user` (token header), `_user_alt` (header OR `?token=` query), `_admin` (must have changed default password), `_admin_saja`, `_user_lokasi` (RBAC per lokasi). RBAC table `hak_akses(id_pengguna, id_lokasi)`; admin = all, petugas = assigned only.
- `app/detection.py` — parallel engine: `DetectionEngine` orchestrator thread + one `KameraWorker` thread per camera (own VideoCapture + YOLO). Frame cache JPEG per worker → live view. `set_mode(auto|yolo|simulator)`; auto falls back to simulator when no stream open. YOLO classes: car/motorcycle→motor, bus/truck→bus.
- `app/kripto.py` — Fernet encrypt/decrypt for RTSP passwords; key at `data/device.key` (auto-created, never delete — stored passwords become undecryptable).
- `app/database.py` — schema + migrate() (adds VMS columns, backfills from legacy url_rtsp). `app/logic.py` — sanitized public snapshot, lisensi, RBAC helpers, retention purge. `app/seed.py`, `app/simulator.py`, `app/alerts.py`, `app/auth.py` (PBKDF2, in-memory tokens 8h).
- Frontend: `templates/admin.html`, `static/admin.js` (renderWall video wall, garis editor over real frame, RBAC hides), `static/style.css` (.wall-live/.sel-live), `static/i18n.js`. Public board separate.

## VMS features (all shipped)

Device model (host/port/kanal/zona/merk, password Fernet-encrypted), license quota (`lisensi` table, PUT admin-only, POST kamera checks quota), unique (host,kanal), GET /api/kamera requires auth, `/api/kamera/semua` + `/snapshot` + `/stream` (MJPEG), retention purge (`retensi_hari` in pengaturan, purge every 6h), RBAC per location.

## Pitfalls (learned the hard way)

1. **engine.stop() kills the simulator too.** The admin UI "⏸ Jeda" button POSTs `{running:false}` → engine stops TOTALLY → capacity numbers freeze. Simulator must always run (demo). Frontend guard: block jeda when `mode_efektif === "simulator"`. To recover: POST /api/deteksi `{"running":true}`.
2. **Stream endpoints + `<img>` need token via query**, but downstream guard `_user_lokasi` re-auths from header only → valid query token gets 401. Fix: thread the token param through: `_user_lokasi(request, lokasi_id, token)` and `_admin_alt(request, token)`.
3. **MJPEG stream never ends** — curl hangs. Always `curl --max-time N` when testing /stream.
4. **MSYS curl pipe quirk** — exit code 23 when piping; use `-o file` per request, or python urllib from execute_code.
5. **Session tokens are in-memory** — restarting the server invalidates all logins. Re-login after every restart.
6. **DELETE /api/pengguna blocks self-delete** (guard) — deleting a test admin account requires another admin.
7. Deleting a user via API does NOT cascade hak_akses rows — orphan rows remain; clean with `DELETE FROM hak_akses WHERE id_pengguna NOT IN (SELECT id FROM pengguna)`. **FIXED 2026-08-03:** `api_pengguna_hapus` now also deletes `pengguna_permissions` rows (3 DELETEs). Orphan cleanup for old DBs: also run `DELETE FROM pengguna_permissions WHERE id_pengguna NOT IN (SELECT id FROM pengguna)`. See Role permission section.
8. `run.py` prints "admin / admin123" banner but real passwords were reset — banner is stale text, don't trust it.
9. **Public display "tidak jalan" ≠ engine bug.** Simulator counters (masuk/keluar) accumulate forever — after days they exceed `kapasitas_maks` (e.g. mobil terpakai 870 > kapasitas 100) → every card stuck PENUH, tersedia 0, looks frozen. Diagnose: hit `/api/state?lokasi=N` twice 6s apart and check numbers move, plus `/api/deteksi` running=true. If counters move but cards show 0/penuh: data overflow, needs reset (item 10).
10. **Reset data simulator** (shipped, v2 2026-08-02): POST /api/deteksi `{"reset":true}` (admin-only) zeroes `masuk`/`keluar` on ALL kapasitas rows + `engine.deteksi_total` + DELETEs all four history tables (`riwayat_deteksi`, `riwayat_koreksi`, `riwayat_kapasitas`, `riwayat_alert`), broadcasts live. UI: "🔄 Reset Data Simulator" button in tab Deteksi (admin-only, confirm dialog warns counters AND all history cleared). Counters re-grow from 0 immediately. User explicitly wanted history cleared too — keep it that way.

11. **Native `confirm()` dialogs block the whole browser harness.** Clicking a confirm()-gated button (e.g. Reset Data Simulator) via browser tools hangs EVERY browser call (navigate/console/press all return "A JavaScript confirm dialog is blocking the page"; no accept/dismiss tool exists; `window.confirm=()=>true` eval also blocked while dialog is open). The dialog state even survives navigation. Workaround: verify confirm()-gated endpoints via curl/API instead of UI clicks; or reload the browser session fresh and override `window.confirm` BEFORE clicking. Don't burn turns retrying the same blocked call.
12. **admin.js `api()` helper always set `Content-Type: application/json`** → breaks FormData file uploads (boundary header stripped → 422). Fix shipped: only set JSON header when `!(opsi.body instanceof FormData)`. Any new multipart endpoint must not fight this helper.
13. **Static cache busting required after any style.css/public.js/admin.js edit** — bump `?v=` in the HTML template or the browser serves the OLD file for the whole session (symptoms: "changes not applied", old CSS classes present). Public.html carries style.css?v=N + public.js?v=N; admin.html carries its own v=.
14. **User DENIES data-writing verification scripts against prod 8090.** A curl POST chain (login → create VMS test record) was hard-blocked; a follow-up read-only python sqlite check + curl GET was also denied (workflow stop). After implementing, verify read-only (GET endpoints, browser UI, `node --check`/`py_compile` for syntax) or hand the user manual browser steps — never POST test data into the production DB uninvited. If a verification command is denied, STOP the workflow and ask, don't retry variants. **Recovery pattern that worked (2026-08-02): after the denial, present 3 options via clarify — (1) restart server + full verification, (2) manual browser steps for the user, (3) adjust the implementation first. When the user answers "lanjukan", they consent to the full verification path — POSTs and sqlite checks then get approved.** A denied command must never be re-issued verbatim; wait for explicit consent.
